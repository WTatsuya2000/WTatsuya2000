    Linux/Macでshell scriptを用いた並列処理

    shファイルの書き方(7/7ver.)

    実行ファイルには許可が必要なので 

        chmod +x run_estimate.sh
    を実行する。

    shファイルの一つの例

    • 例1 
          #!/usr/bin/env bash
    export JULIA_NUM_THREADS=16  # スレッド数を決定する
    mkdir -p Zs/RW               # 必要なディレクトリの作成

    for p in $(seq 1 1 10); do
        echo "[start] p = ${p}"    # echoで書くことができる
        # バックグラウンドで起動
        nohup julia estimate_RW.jl "${p}" "Z${p}_RW.csv" > logs/log_${p}_RW.txt 2>&1 &
        pid=$!                     # 直近のバックグラウンドPIDを取得
        wait $pid                  # このジョブの終了を待つ
        echo "[done ] p = ${p}"
    done

    echo "All jobs done."
    • 例2 
          #!/usr/bin/env bash

    params=(24 32 36 40 48)
    for p in "${params[@]}"; do
        echo "[start] p = ${p}"
        nohup julia LYZ.jl $p > logs/log_${p}.txt 2>&1 &
        pid=$!                     # 直近のバックグラウンドPIDを取得
        wait $pid                  # このジョブの終了を待つ
        echo "[done ] p = ${p}"
    done

    echo "All jobs launched."

    実行は./run_hogehoge.sh

    システムが「忙しい (busy)」状態にあるかどうかは、主に以下の指標で判断します。

    1. ロードアベレージ (load average)

    • 値 が CPU コア数以上に近い／超えている
    • 例：4 コアマシンで load average が 4.0 を超えると、常に４つ以上のプロセスが実行待ち → 忙しい
    • 1 分・5 分・15 分 のうちいずれか、特に 1 分値が高いと即時的に負荷が高いことを示す

    2. CPU 使用率 (%CPU)

    • id（idle） が低いほど忙しい
    • 例：id が 5% → 95% がユーザー／システム処理に使われている → 非常に忙しい
    • us（user）・sy（system） が高いと、多くの計算やカーネル処理に CPU 時間を取られている
    • wa（I/O wait） が高いと、ディスク／ネットワーク待ちで停滞している

    3. スレッド・プロセス数

    • 実行中 (running) が多いほど並列に CPU を使おうとしている
    • D (uninterruptible sleep: I/O 待ち) が多いと I/O ボトルネック発生中

    4. メモリ・スワップ

    • 物理メモリの使用率 が非常に高く（used＋buff/cache ≃ total）、free がほぼ 0
    • スワップ使用量 (Swap used) が増えていると、物理メモリ不足でディスクを参照 → 大幅に遅くなる

    まとめ：

    • 忙しい状態
    • Load average ≥ CPU コア数
    • %idle が 10% 未満（または us＋sy＋wa 合計が高い）
    • スワップ使用量が増加中
    • 実行中プロセス数が多い or 多数のプロセスが I/O 待ち

    これらの指標が一つでも目立って高／低になっていれば、システムは「busy」と判断できます。```
